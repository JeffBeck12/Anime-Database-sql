# Design decisions

The schema deliberately has exactly six tables. A series has one studio and one primary genre; studios and genres may have zero or many series. Episodes and characters belong to exactly one series. An actor may voice many characters, and each character stores exactly one actor/performance language. A real catalog would add junction tables for multiple studios, genres and multilingual castings. Title uniqueness is a demo simplification; real remakes may share titles. Stored episode counts are derived from Episodes; Ongoing series may have incomplete coverage. IDs identify entities independently of names. Episode numbers and character names are unique per series. Parents cannot be deleted while referenced; delete children explicitly first. No total-episode or runtime field is duplicated in Anime_Series. Dates relative to release year are a dataset validation rule, not a cross-table CHECK.

The schema creates tables without dropping existing data. Seed loading is one transaction; if an error occurs in an interactive client, issue ROLLBACK before proceeding. Re-running the seed fails on primary keys. Use a fresh empty database for this demonstration.
